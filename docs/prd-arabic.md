# وثيقة متطلبات المنتج لمشروع معامل هندسة البرمجيات: ميقات (Miqat)

**اسم المشروع:** ميقات (Miqat)  
**السياق:** مشروع معمل / مادة هندسة البرمجيات بالجامعة  
**إصدار الوثيقة:** 1.4 (المواصفات النهائية للمعمل)  
**نسق الألوان الرئيسي:** الأزرق الكهربائي الحديث (`#2563EB`) مع الرمادي الداكن (`#0F172A`)

## 1. نظرة عامة على المشروع

**ميقات** هو بيئة عمل حديثة وموحدة لإدارة الوقت، تهدف إلى الدمج بين تصنيف المشاريع، وتتبع المهام، والجدولة الزمنية، ومؤقت التركيز (بومودورو - Pomodoro) في تطبيق واحد متكامل.

يعرض المشروع المبادئ الأساسية لهندسة البرمجيات، المعمارية متعددة الطبقات (Multi-tier architecture)، تصميم واجهات برمجة التطبيقات (RESTful API)، دعم نظام الأنماط (الوضع الداكن والفاتح)، والتكامل عبر المنصات المختلفة (تطبيق ويب وتطبيق جوال) ضمن إطار الفصل الدراسي الجامعي.

## 2. أهداف المشروع والأمور الخارجة عن النطاق (Goals & Non-Goals)

لضمان إنجاز المشروع ضمن الموعد النهائي للمعمل وتحديد حدود التقييم بوضوح، تم تقسيم نطاق المشروع إلى **أهداف أساسية** و**أمور خارجة عن النطاق**.

### 2.1 الأهداف الأساسية (تسليمات النموذج المبدئي MVP)

* **مصادقة المستخدمين (Authentication):** تطبيق نظام تسجيل ودخول آمن باستخدام رموز JWT لحسابات المستخدمين عبر الويب والجوال.

* **تصنيف المشاريع:** تمكين المستخدمين من إنشاء وإدارة المشاريع برمز ألوان مخصص لتنظيم أوقات العمل.

* **إدارة كاملة للمهام (CRUD):** توفير إدارة كاملة للمهام (إنشاء، قراءة، تعديل، حذف) مع خيارات تصفية حسب المشروع، الأولوية، وحالة الإنجاز.

* **مؤقت بومودورو مدمج:** تنفيذ مؤقت تنازلي (25 دقيقة تركيز / 5 دقائق استراحة)، مع إمكانية تسجيل جلسات التركيز مباشرة ضمن مهام محددة.

* **عرض أجندة/تقويم بسيط:** عرض المهام بصرياً وفقاً لتواريخ استحقاقها في شكل أجندة يومية أو أسبوعية.

* **تبديل الوضع الداكن والفاتح (Dark/Light Mode):** دعم مفتاح تبديل سلس بين الوضع الفاتح الحديث والوضع الداكن (`#0F172A Slate Dark`) عبر عميل الويب (Next.js) والجوال (Flutter).

* **تطبيق يعمل عبر المنصات:** بناء عميل ويب متجاوب (Next.js) وتطبيق جوال (Flutter) يستهلكان واجهة برمجة تطبيقات REST مشتركة (NestJS أو Express).

### 2.2 الأهداف الإضافية (قائمة الرغبات / ما بعد الـ MVP)

* **التخزين المحلي للجوال دون اتصال بالإنترنت (SQLite / `sqflite`):** حفظ المهام محلياً على الجوال لعرضها عند عدم توفر إنترنت، مع المزامنة مع الخادم فور الاتصال.

* **إحصائيات إنتاجية بسيطة:** عرض إحصائيات مجمعة بسيطة (مثل إجمالي دقائق التركيز لكل مشروع).

### 2.3 أهداف خارج النطاق (مستبعدة صراحةً)

* **التعاون متعدد المستخدمين:** لا يوجد مشاريع مشتركة، أو عمل جماعي لحظي، أو أدوار صلاحيات (حساب فردي فقط لكل مستخدم).

* **التكامل مع تقويمات خارجية:** لا توجد مزامنة مع Google Calendar أو Apple Reminders أو Outlook.

* **المزامنة اللحظية المعقدة:** لا يوجد محرك WebSockets أو آليات معقدة لحل النزاعات بين أجهزة متعددة تعمل في نفس الوقت.

* **الجدولة الذكية/الذكاء الاصطناعي:** لا توجد خوارزميات ذكاء اصطناعي أو جدولة تلقائية للمهام.

* **بنية تحتية معقدة للإنتاج (DevOps):** لا توجد خدمات مصغرة (Microservices) معقدة أو كلاسترات Kubernetes (يكفي الاستضافة المحلية أو الرفع البسيط على منصات مثل Render/Vercel).

## 3. مواصفات التقنيات المستخدمة (Tech Stack)

| الطبقة | التقنية | المسؤوليات الرئيسية |
| ----- | ----- | ----- |
| **واجهة الويب (Frontend Web)** | React / Next.js (TypeScript) | عميل الويب، واجهة متجاوبة، لوحة التحكم الرئيسية، وسياق نمط الألوان (Dark/Light Mode). |
| **واجهة الجوال (Frontend Mobile)** | Flutter (Dart) | تطبيق Android و iOS مع دعم للوضع الداكن والفاتح. |
| **خادم الخلفية (Backend API)** | NestJS أو Express.js (TypeScript) | خادم REST API نمطي (Modular)، مصادقة المستخدمين، وقواعد العمل (Business Logic). |
| **قاعدة البيانات (Database)** | PostgreSQL (مع TypeORM أو Prisma) | تخزين البيانات 관계ية (المستخدمون، المشاريع، المهام، جلسات التركيز). |
| **المصادقة (Authentication)** | JWT (JSON Web Tokens) | تفويض المستخدِمين بدون الحاجة لتخزين جلسات على الخادم (Stateless). |

## 4. المتطلبات الوظيفية والتقنية للنموذج المبدئي (MVP)

### 4.1 معمارية الخلفية ومخطط قاعدة البيانات

#### **كيانات قاعدة البيانات (Entities)**

1. **كيان المستخدم `User`:** `id`, `email`, `password_hash`, `full_name`, `created_at`

2. **كيان المشروع `Project`:** `id`, `name`, `color_code`, `description`, `user_id` (مفتاح أجنبي)

3. **كيان المهمة `Task`:** `id`, `title`, `description`, `status`, `priority`, `due_date`, `project_id` (مفتاح أجنبي اختياري), `user_id` (مفتاح أجنبي)

4. **كيان جلسة التركيز `FocusSession`:** `id`, `duration_minutes`, `completed_at`, `task_id` (مفتاح أجنبي اختياري), `user_id` (مفتاح أجنبي)

#### **مسارات واجهة البرمجة (REST API Routes)**

* **المصادقة (Auth):**

  * `POST /api/auth/register` — إنشاء حساب جديد.

  * `POST /api/auth/login` — إرجاع رمز JWT.

* **المشاريع (Projects):**

  * `GET /api/projects` — جلب مشاريع المستخدم.

  * `POST /api/projects` — إنشاء مشروع جديد.

  * `DELETE /api/projects/:id` — حذف مشروع.

* **المهام (Tasks):**

  * `GET /api/tasks` — جلب مهام المستخدم (مع إمكانية التصفية: `?status=`, `?projectId=`, `?dueDate=`).

  * `POST /api/tasks` — إنشاء مهمة.

  * `PUT /api/tasks/:id` — تحديث الحالة، الأولوية، أو التفاصيل.

  * `DELETE /api/tasks/:id` — حذف مهمة.

* **جلسات التركيز (Focus Sessions):**

  * `POST /api/sessions` — تسجيل دورة بومودورو مكتملة.

  * `GET /api/sessions/summary` — استرجاع ملخص عدد الجلسات ودقائق التركيز.

## 6. التقييم الأكاديمي ومؤشرات النجاح

| فئة المؤشر | المعيار / الهدف | طريقة التقييم |
| ----- | ----- | ----- |
| **الإنجاز الوظيفي** | تنفيذ 100% من أهداف الـ MVP الأساسية (المصادقة، المشاريع، المهام، المؤقت، الوضع الداكن). | العرض المباشر في المعمل (Live Demo) |
| **معمارية البرمجيات** | فصل سليم للطبقات (Controllers, Services, Repositories). | مراجعة الكود المصدري |
| **تصميم قاعدة البيانات** | مخطط علاقات سليم ومنظم (Normalized) مع قيود المفاتيح الأجنبية. | فحص مخطط العلاقات (ERD) |
| **جودة واجهة البرمجة (API)** | مسارات RESTful واضحة، استخدام صحيح لرموز حالات HTTP، معالجة أخطاء مناسبة. | اختبار مجموعة Postman |
| **جودة الواجهات والتصاميم** | واجهة ويب متجاوبة (Next.js) وشاشات جوال سلسة (Flutter) مع مفتاح يعمل لتبديل الوضع الداكن/الفاتح. | الفحص البصري |
